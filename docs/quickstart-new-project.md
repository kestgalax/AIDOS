# New Project Quickstart

This guide shows how to use AIDOS when starting a new project through the clone-template workflow.

## Goal

After this flow, the new project has:

- product intent;
- roadmap with stack and dev-environment gates;
- architecture placeholder;
- ADR directory with structure and runtime stack placeholders;
- Planner, Developer, and Reviewer agent instructions;
- feature, task, and review templates;
- tooling scripts for `validate`, `trace`, and `review`;
- validation through `aidos validate`.

## 1. Clone AIDOS And Install Dependencies

```bash
git clone <your-aidos-repo-url> AIDOS
cd AIDOS
npm install
```

During local development, run commands through npm:

```bash
npm exec aidos -- <command>
```

## 2. Initialize A New Project

Recommended workspace layout:

```text
workspace/
  AIDOS/
  my-new-project/
```

Interactive onboarding:

```bash
npm exec aidos -- init ../my-new-project --interactive
```

AIDOS asks about mission, vision, principles, non-goals, planned product form, and initial stack direction.

Non-interactive mode:

```bash
npm exec aidos -- init ../my-new-project
```

Update an existing skeleton:

```bash
npm exec aidos -- init ../my-new-project --update --confirm-overwrite
```

## 3. Follow The Project Lifecycle

Read `docs/onboarding-project-lifecycle.md` in the AIDOS clone.

Key gates:

1. Idea -> product intent
2. Stack ADR gate -> accept `docs/decisions/ADR-002-runtime-stack.md`
3. Dev environment -> document in `ops/environments.md`
4. First feature -> `aidos new flow`

## 4. Validate The Created Project

```bash
cd ../my-new-project
npm run aidos:validate
```

Or from the AIDOS clone:

```bash
AIDOS_ROOT=. npm exec --prefix ../my-new-project node ../my-new-project/scripts/run-aidos.mjs validate
```

Expected result:

```text
AIDOS validation passed
```

## 5. Create The First Traced Feature Flow

From the new project directory:

```bash
npm exec --prefix ../AIDOS aidos -- new flow "first user workflow"
```

This creates linked feature, task, and review artifacts with traceability autofill.

Check traceability:

```bash
npm run aidos:trace
```

Run review gate:

```bash
npm run aidos:review
```

## 6. Optional Dashboard Scaffold

```bash
npm exec --prefix ../AIDOS aidos -- new dashboard ./dashboard
```

The dashboard starter lives in `examples/dashboard-starter/` inside the AIDOS clone.

## 7. CI Governance

See `docs/ci-governance.md` in the AIDOS clone and `ops/ci.md` in the new project.

Minimum pipeline:

```bash
npm run aidos:validate
npm run aidos:trace
npm run aidos:review
```

## Living Consumer

In-repo examples are scaffolds. A **living consumer** is an external product that runs AIDOS in production development.

The first documented living consumer is [CarrotType](https://github.com/kestgalax/carrottype) (private / invite-only macOS dictation app). Recommended workspace layout:

```text
workspace/
  AIDOS/
  carrottype/
```

Inspect its intent, ADRs, roadmap, and `aidos.config.json`. Full notes: `docs/living-consumers.md`.

## Current Limitations

- AIDOS is used from a cloned repository, not as a published npm package.
- Application runtime scaffold is intentionally not generated by `aidos init`.
- Reviewer automation is deterministic and checks markdown artifacts only.
